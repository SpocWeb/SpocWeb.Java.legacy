Tensor Multiplication is a complicated linear Transformation.

What happens on generically multiplying Sum(j, a[i,j,k]*b[l,j,m]) ?= a[i,k,l,j,m]  ?= a[i,j,k,l,m]  ???

            The Structure of A cannot be reused for storing the Result

            The outer Structure of B cannot be reused for comfortably calculating the Values.

Instead you have to create a new Structure recursively and fill it up with the Product recursively using a MultiIndex.

 

The Tensor Products can be of different Type:

  • dyad() c[i,j] = a[i]*b[j] being of (possibly) different Dimension Grad(a.dyad(b))==Grad(a) + Grad(b)
  • mul  () c[i  ] = a[i]*b[i]  being in the same Dimension Space Grad(a.mul(b))==Grad(a)==Grad(b)
  • cat () c      = Sum(i, a[i]*b[i] = Sum(i, a.mul(b)) , the Scalar Product, also being in the same Dimension Space Grad(a.cat(b))==Grad(a) + Grad(b) - 2

 

The generic Tensor Products can also be of different Type:

  • dyad () c[i,j,k,l,m,n] = a[i,j,k]*b[l,m,n] being of (possibly) different Dimension
  • mul  () c[i,j,k] = a[i,j,k]*b[i,j,k]  being in the same Dimension Space and same Tensor Degree
  • short() c[i,k,l,n]      = Sum(j, a[i][j,k]*b[l,j,n] = Sum(j, a.mul(b)) , the Scalar Product, also being in the same Dimension Space

 

 

 

The regular case is multiplying a Tensor by a Matrix.

Transforming a Tensor into a different Coordinate Space requires transforming each Degree by the same Matrix:

y[i] = a[i][j] * x[j] è Y[i1,i2,i3] = a[i1][j1] * a[i2][j2] * a[i3][j3] * X[j1,j2,j3]

Since the Degree of the Tensor stays the same, it can be manipulated in Place.

 

The outer Structure stays the same and is reused to store the result.

The inner Structure is accumulated from the Product.

 

A.mapAt(B) == B.catAt(A) returns B in Place.

a[i,j,k]*b[k,l,m] = a[i,j,k,l,m] can be directly stored in the structure of A using Element Copies of b.

 

The unshortened Product fits into the Structure of a and replaces it completely: a[i,j,k]*b[k,l,m] = a[i,j,k,l,m]  == A.catAt(B) ==

The shortened Product also fits into the Structure of a, except for the lowest Level, which is thrown away! a[i,j,k,l,m] è a[i,j,l,m]

It would be identical to the Manifold Product, but only at the innermost Level: A.catAt(B) = A.mulAt(B).SumAt(), but mulAt() does not retain the Structure! Instead of a Scalar it becomes a Tensor, which does not lend itself to any Optimization!

 

A correct Description would be a[i][j][k] = B.mul(a[i][j][k]) , where you cannot use B.mulAt(), because you need the original B for any Element a[i,j,k] and then summing it up: a[i][j] := Sum(k, a[i][j][k])

 

a[i,j,k]*b[k,l,m] == a[i[j[k]]]*b[k[l[m]]] == a[i,j,k,l,m] == a[i[j[k[l[m]]]]] == a[i,j][k,l,m] 

 

 

When multiplying by a Matrix (special Case) , the Degree stays the same, but the Dimension may change (e.g. increase from 2 to 3 because of a Rotation in Space!). Thus the Structure cannot be directly reused!

Set of Objects with Operation ° called 'map()' on any two Objects.

I.e. in a HalfMonoid any two Objects can be "concatenated" or "mapped".

Example is e.g. String Concatenation or Function Concatenation / Mapping.

This Concatenation is associative i.e. (a°b)°c==a°(b°c) but not commutative!

Therefore pairs of Operations can be defined:

map()/unMap() with the Operand coming from the left and

cat()/unCat() with the Operand coming from the right

 

It can be proven that:

 

!(A°B)== !B°!A

[A,A] == [A,!A] == [A,Id] == 0

A°!A == !A°A == Id == A.unMap(A) == A.unCat(A) == A.solve(A) == A.reSolve(A)

 

  A.map(A .unMap(w))==  A°!A°w == w == A.unMap(A .map(w))== !A° A°w

  with w being a simple Object, a Map or a Monoid.

b == A°a == A.map(a)  and  a == !A°b == A.unMap(b)
