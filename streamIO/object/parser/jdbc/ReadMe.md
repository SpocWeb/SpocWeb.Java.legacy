# jdbc

This Subsystem implements a minimal JDBC Driver (`DriverSep`, registering under the `jdbc:...sep:`
URL Scheme) whose "Database" is a Directory of separated-Format Files - Comma-, Tab- or
custom-Separator delimited, one File per Table. `ConnectionSep` resolves Table Names to Files based
on the Connection's configured Path, Suffix and Separators, and hands out `StatementSep`/
`PrepStatementSep`/`CallStatementSep` for running simple Queries with no Joins and no Conditions
beyond resolving the Table Name itself. `ResultSetSep` does the actual Row-by-Row Parsing (reusing
`streamIO.object.parser.InputStream2StreamIn`) and Row-level Insert/Update/Delete by appending
Log-style Entries rather than rewriting the File in place, with `compress()` available to reclaim
Space by dropping superseded Rows. `ResultSetToSax`/`ResultSetToNestedSax` feed any JDBC `ResultSet`
(not just this Package's own) through a SAX `ContentHandler` to build an XML `Document`, complementing
the parent `parser` Package's XML-writing Classes. Several JDBC Interface Methods here are
intentionally partial - `CallStatementSep`/`PrepStatementSep.getResultSet(File, String)` are
unimplemented Stubs, and multiple `ConnectionSep.prepareStatement(...)` Overloads silently ignore
Parameters (autogenerated Keys, Column Indexes/Names) that this simple Store cannot honor.
