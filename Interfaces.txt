no Prefix for Parameters

Capital Start Character for Classes

Create separate Packages to collect: 
Interface Classes starting with I	those must be shared as Base for Interop 
Abstract Classes starting with A	those are possibly shared, since small 
Test Classes starting with T	those are not delivered 
Implementation Classes 		these are only half worth without Testing Code

Make the Read only Interfaces the Base Interfaces
e.g. IBoole (for finite Enum Boolean Logic) or IProcessor Map instead of MapAt etc.

Refactorings: 
* All Methods taking Arrays with Start and End Index should have the End Index optional and 
THEN the Start Index. 
* All CopyAble Methods should have Methods like add(a, b, c) to perform c = a + b 
	addAt(a, b) could then be implemented as add(a, b, a) and 
	add(a, b, c) could be implemented as c.copyAt(a); c.addAt(b); 
	
* no static Methods should have an _AT Suffix, because they receive all Parameters anyway.

Wenn alle Relationen bidirektional navigierbar sind
(und nicht nur von N => 1),
dann erhält sich jeder Baum im Speicher,
egal ob Ref-Counting oder Garbage Collection!
Zu verhindern ist dies durch
-ungültige Referenzen
-weak References! (werden ggf. bei GC gelöscht)

Neben expliziten Relationen (über Member Variable)
müssen auch implizite Relationen möglich sein,
die in einer WeakHashMap gespeichert werden.

Offen ist die Frage, ob 1:N und N:M Relationen
in derselben Weise gespeichert werden.
